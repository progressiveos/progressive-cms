# Progressive CMS SEO

Доведи сайт до проверенного состояния по всем применимым пунктам [матрицы аудита](references/audit.md), исправляя первопричины, а не только перечисляя замечания. Цель — отсутствие открытых устранимых ошибок индексации/метаданных/рендеринга и зафиксированные результаты остальных применимых оптимизаций. Позиции, включение в индекс и вид сниппета выбирают поисковые системы; не обещай первое место, мгновенную индексацию или «100 баллов = идеальное SEO».

## Перед работой

1. Определи разрешённые origin/site/environment, текущий production host, языки/регионы, назначение страниц, приоритетные действия посетителя и доступы. Используй уже данное разрешение на SEO-правки; не спрашивай повторно про каждый title. Смена домена/URL, массовое снятие с индекса, удаление содержимого, инфраструктура и аккаунты поисковиков требуют подтверждённой политики/полномочий именно на это действие.
2. Прочитай `cms agent bootstrap --json` и [manifest.json](manifest.json), затем [контракты PCMS](references/pcms-workflow.md). `cms capabilities` — локальный каталог, не эффективные права connected actor. Core read-only; нет операции — короткий Core handoff, не SQL и не дублирование защищённого head в теме.
3. Проверь текущие официальные [источники](references/sources.md). Разделяй обязательные требования поисковой системы, рекомендации и выбранную политику проекта. Не превращай привычку SEO-специалиста в алгоритмический закон.

## Обход и исправления

- Объедини sitemap, маршруты/Content Tree, ссылки реального сайта и известные старые URL. Веди нормализованный URL ledger: статус/редиректы, robots, canonical, indexability, title/description, видимый H1/иерархия, язык, OG/JSON-LD, медиа, внутренние входы, группа дублей, результат. URL с query не сливай до проверки семантики.
- Для небольшого сайта проверь все внутренние HTML-страницы. Для большого задай явный лимит обхода/скорости, сохрани очередь и отметь непроверенный остаток. Пройдись по всему доступному реестру метаданных/группам дублей, а рендер/нагрузочные показатели проверяй на представителях каждого шаблона и исключениях. Выборку не называй полным обходом.
- Сначала доступность/статусы/индексация/каноникализация, затем общие шаблоны и head, потом индивидуальные поля, ссылки/медиа/разметка и производительность. Одна ошибка layout обычно исправляется один раз для всех страниц.
- Изменяй данные через публичные операции: используй CAS там, где он предусмотрен; SEO/Site Identity полностью заменяются без CAS (см. workflow). SEO хранится отдельно от контентных полей, но `title`, intro, hero, Content Tree и опубликованная revision участвуют в fallback. Сохрани намеренную издательскую политику и реальные факты; не генерируй повторяющиеся рекламные заголовки на все страницы.
- После исправления шаблона повтори проверку всех затронутых URL/групп, а после исправления отдельной страницы — её и зависимые canonical/hreflang/ссылки. Preview и source-тест не заменяют публичный HTML после авторизованной публикации.

## Строгость без SEO-мифов

На индексируемой странице нужен один авторитетный `<title>`, согласованные canonical/robots и осмысленная основная тема. **Один видимый основной H1 — политика этого workflow**, а не отдельный универсальный запрет Google на несколько H1. Не создавай второй H1 из логотипа/мобильной копии; осмысленное исключение документируй. Title и H1 не обязаны дословно совпадать; общие заголовки секций на разных страницах не являются автоматически вредными дублями.

Не выставляй искусственные лимиты длины title/description как критерий индексации, не заполняй meta keywords ради «галочки», не навешивай alt с ключами на декоративные картинки, не канонизируй все страницы пагинации на первую. Не подделывай отзывы, цены, автора, даты изменения, региональное присутствие, FAQ/HowTo-eligibility или результаты измерений.

Аналитика, Вебвизор, внешние шрифты и маркетинговые пиксели не обязательны для SEO. Соблюдай разрешённый режим обработки данных; не включай трекинг ради приёмки. Cookie/CMP не должны скрывать основной серверный контент от пользователя и робота, но не обходи отказ и не показывай роботам специальный SEO-текст.

## Результат и остановка

Для каждого пункта матрицы укажи `PASS / FIXED / FAIL / BLOCKED / N/A`, факт/источник и URL/доказательство. Устрани все доступные в разрешённой области ошибки, а не прекращай после первых пяти. Применимую оптимизацию, которая невозможна без Core/инфраструктуры/аккаунта/реальных бизнес-данных, отметь с точным следующим действием; это не `N/A` и не успешная приёмка.

Заполни [отчёт](assets/acceptance.md): изменения, до/после, охват, оставшиеся блокеры, external provider acceptance. После одного полного обхода повторяй затронутые проверки по изменениям; не запускай бесконечные полные краулы ради случайных различий оценщика. Заверши, когда все применимые проверки закрыты либо явно заблокированы вне выданных полномочий. Общий «идеальный SEO» не заменяет этот проверяемый критерий.

Если доступны только файлы без целевой CMS/сети, выполни статическую часть и подготовь reviewable изменения; не помечай их применёнными и не ставь PASS серверной/полевой приёмке.
