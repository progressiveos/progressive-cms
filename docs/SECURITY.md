# Security policy

Progressive CMS is in Public Beta. Report suspected vulnerabilities privately; do not post exploit details, credentials, customer data or unpatched security findings in a public issue, discussion or pull request.

When private vulnerability reporting is enabled for the GitHub repository, use the repository's **Security → Report a vulnerability** flow. If that option is unavailable, contact Progressive OS through its [official contact page](https://p-cms.com/contacts/) and ask for a secure disclosure channel before sending technical details. Do not attach secrets or personal data to the public contact form.

Include the affected release, a concise impact summary, reproduction steps that do not access another person's data, and any relevant sanitized logs. Allow maintainers reasonable time to acknowledge, investigate and coordinate a fix before public disclosure. Do not probe systems or sites you do not own or have explicit permission to test.

The current target is the Progressive CMS 1.0 Public Beta. Reports are assessed against the latest official release and the actual affected code. No response-time or patch guarantee is implied. The project does not currently publish a separate security support window for every historical prerelease.
