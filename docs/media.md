# Media Library

Contract owner: Core MediaAsset.

Reuse or upload MediaAssets through the public Media Library. References preserve asset identity; delivery URLs and derivative paths are resolved by Core. Validate file type, size, dimensions and processing results rather than accepting a URL as proof of safe media.

Original media storage and quarantine must survive release updates. Derivatives are generated by registered presets. Core owns `og-v1` social images (1200 × 630 JPEG) and favicon derivatives. Social derivatives materialize at semantic assignment/preview/validation/publication points, not on every crawler request.

## Derivative generation reports

When generation of a theme preset fails, Core still accepts the image asset and returns optional `media_variant_failures` entries (`media_id`, `preset`, `error`). The field is omitted when no preset failed. Admin shows a localized warning naming the failed presets; the asset remains available, but those derivatives are unavailable. Existing endpoint permissions and storage schema are unchanged.

| Request | Failure report |
|---|---|
| `POST /api/v1/media` (201) | Top-level `media_variant_failures` in the upload response. |
| `POST /api/v1/media/import` (201) | Top-level field in the remote-import response. |
| `POST /api/v1/media/stock/import` (200) | Top-level field on a new import. A duplicate re-import returns the existing asset without rerunning variant generation; any warning belongs to the original import response. |
| `POST /api/v1/media/generations/{generationId}/candidates/{candidateIndex}/accept` (200) | Top-level field on a new accept or replay, when failures were recorded. |
| `GET /api/v1/media/generations/{generationId}` (200) | `candidates[].media_variant_failures` when background auto-import failed to create presets; the status preserves those failures for replay. |
| `.pcpub` ingest status | `result.media_variant_failures` may report failures per bundled asset even when ingest completes. |

For `.pcpub` ingestion, the worker refreshes its presets from the persistently active theme before processing each package. `themes.renderDir` is the configured fallback directory, not a reliable indication of which theme is active.

Existing images are not automatically backfilled when presets change. Regenerate one asset's current active-theme variants with `POST /api/v1/media/{mediaId}/variants/regenerate`; the request has no body and requires the existing `media.write` permission. It is idempotent, preserves the MediaAsset ID, original bytes and version, and returns `media_id`, `generated`, `reused`, plus optional `media_variant_failures` when some presets still fail. Retry the operation after addressing a reported failure; already present variants are reused.

The equivalent MCP tool is `cms_regenerate_media_variants` with `{"media_id":"<media-id>"}`. Admin exposes the same action in Media Details for writable raster images. This is a single-asset operation; there is no bulk backfill. Archived assets return `MEDIA_ARCHIVED` (409), SVG and other non-raster assets return `MEDIA_VARIANT_REGENERATION_UNSUPPORTED` (422), missing assets return `MEDIA_ASSET_NOT_FOUND` (404), and unavailable storage or active presets return `MEDIA_STORAGE_CONFIG` or retryable `MEDIA_PRESETS_UNAVAILABLE` (503). `PUT /api/v1/media/{mediaId}/version` replaces document assets and rejects images with `MEDIA_IMAGE_REPLACEMENT_FORBIDDEN`; do not use document version replacement to repair image derivatives.

Published-card selection and its explicit-hero behavior are described below. Card covers and OG images have different resolution rules; never add invisible blocks to drive a cover.

Use `cms media usage` before archival and inspect references. Give each card an explicit, confirmed image source or render it without a cover. A Page Hero is not automatically the card or social image. See [SEO](seo.md).

Extension media-usage sources continue to guard references from disabled extensions and from uninstalled extensions whose data is retained. Keep the trusted package and source handler available so Core can inspect those references. If the package or handler is missing, Core fails closed and blocks deletion instead of treating the asset as unused; there is no force-delete bypass.

## Authoring and template example

`POST /api/v1/media` accepts raw file bytes with `Content-Type: application/octet-stream` and required `X-PCMS-Filename` (1–255 characters). Optional `X-PCMS-Mime-Type` declares the file MIME type, and optional `X-PCMS-Folder-Id` selects a folder; neither bypasses ingestion validation. Successful upload returns HTTP 201 with `media_id`, `version_no`, `sha256`, `size_bytes`, `mime_type` and `duplicate_blob`, plus optional `media_variant_failures` if preset generation failed. `media.write` is distinct from URL import/provider permissions. Use the returned `media_id`, set accessible alt text, and discover the theme's presets. URL import must pass the product's acquisition checks; do not import private URLs or bypass quarantine.

```liquid
{% assign picture = media[entry.fields.hero_image].presets.card %}
{% if picture %}
<img src="{{ picture.src }}" srcset="{{ picture.srcset }}" alt="{{ picture.alt }}" loading="lazy">
{% endif %}
```

The active theme must declare `card`; missing assets/derivatives remain absent. For published cards, a nonempty explicit hero_image is the only candidate; if it lacks the needed derivative, there is no block/original fallback. With no explicit hero, Core visits published image/gallery blocks in document order and chooses the first eligible card derivative. A prose document should not acquire hidden blocks for this purpose.
