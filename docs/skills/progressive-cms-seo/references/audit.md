# Матрица SEO-аудита и исправлений

Источники G/Y/O перечислены в [sources.md](sources.md). У каждого пункта должен быть результат; неприменимость требует причины. Сначала зафиксируй страницу/шаблон/намерение, потом меняй. Для Google и Яндекса проверяй требования отдельно там, где они отличаются.

## A. Доступность, обход, политика индексации

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S01 | Канонический production host, HTTPS, DNS/TLS, ответы для пользователя и роботов | Целевые страницы — стабильный 200; не маскируй 401/403/429/503, maintenance, TLS/DNS-сбой или WAF challenge как SEO noindex. Проверить нужные варианты host/HTTP/slash. Изменение RP/DNS только в согласованном контуре. | G1, Y1 |
| S02 | Статусы удалённых/перемещённых URL и цепочки | Реальная 404/410 для отсутствующего; не soft-404 и не массовый редирект на главную. Постоянный релевантный перенос — 301/308 в один переход, без циклов. Не менять успешные URL ради косметического SEO. Сохрани старые ссылки и план отката. | G1, G3, Y2 |
| S03 | robots.txt на каждом участвующем origin | 200/правильный text/plain; группы User-agent и disallow не закрывают нужные страницы/JS/CSS/медиа; корректный Sitemap. Robots не средство авторизации и не гарантированное удаление URL из индекса. Не используй неработающую директиву `Noindex:` в robots. | G4, Y3 |
| S04 | meta robots и X-Robots-Tag | Политика по типам страниц: production посадочные разрешены; staging/preview/личные/служебный поиск защищены по назначению. Noindex должен быть доступен роботу для чтения: Disallow может помешать его увидеть. Учитывай заголовок ответа и несколько meta; не снимай environment guard из темы. | G4, G1, Y1 |
| S05 | Sitemap/XML | Только предназначенные для индексации канонические доступные URL; исключи redirect/404/noindex/private/preview/фильтровый мусор. `lastmod` — фактическое существенное изменение, не время каждого запроса. URL encoding, XML escaping, размер до 50 000 URL/50 MB uncompressed на sitemap, индексы/хосты. `priority`/`changefreq` не способ заставить Google переобходить. | G5, Y3 |
| S06 | Crawl coverage, сироты и ловушки | Сопоставь sitemap, внутренние ссылки, CMS registry и разрешённые Search Console/Webmaster данные. Найди сироты, бесконечные календари, комбинации параметров, поисковые/теговые архивы. Исправь навигацию и политику параметров; не прячь полезный раздел только ради снижения числа URL. | G1, G3, G7, Y2, Y4 |

## B. Дубли и URL

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S07 | Canonical один, абсолютный и согласованный | В HTML head или поддерживаемом HTTP header (например PDF), не конфликтующие значения. Для индексируемого уникального документа — self canonical с 200/indexable target; убери query-мусор, проверь hostname/protocol/path. Redirect, canonical, sitemap и internal href указывают согласованную версию. Canonical — сигнал, не обещание выбора поисковиком. | G3, Y2 |
| S08 | Кластеры точных и близких дублей | Нормализуй без учёта шапки/подвала и проверь смысл: несколько URL одного документа, зеркала, print, tracking, языки, разница slash/case. Выбери перенос/каноникализацию/разведение намерений; не переписывай весь сайт механически ради уникальных строк. Canonical не подходит для разных содержательных страниц. | G1, G3, Y2 |
| S09 | Фильтры и параметры | Изменяющий содержание фильтр/страница не равен utm/session-id. Определи индексируемые полезные посадочные, остальные ограничь согласованной политикой. Yandex Clean-param только для действительно не влияющих на содержание параметров; это не Google-директива и не замена редиректам/защите. Не обещай Core-опцию, если её нет. | G3, Y4 |
| S10 | Пагинация, infinite scroll/load more | У каждой содержательной страницы собственный URL и self canonical; next/previous доступны через обычные href. Не canonical page 2 → page 1; не рассчитывай на кнопку/scroll как единственный путь. Политика noindex и фасетов осмысленна; фиксированная серверная page identity и границы без пустых бесконечных 200. | G7, G8 |

## C. Title, description и заголовки

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S11 | Один непустой `<title>` в head, назначение понятно | Информативный, соответствует странице/языку/видимому основному заголовку; бренд без повторного суффикса, без списка ключей, placeholder/«Главная» на всех URL. Найди точные/шаблонные/почти одинаковые title по всему ledger. Осмысленные однотипные страницы отличай существенным признаком. | G2, Y1 |
| S12 | Description и сниппет | Не более одного authoritative meta description; индивидуальное полезное резюме там, где оно помогает. Исправь пустые/дубли/шаблонный мусор, но не режь юридически точное название ради числа символов. Результат поиска может выбрать иной фрагмент и изменить длину; не обещай его принудительно. | G1, Y5 |
| S13 | H1-политика и визуальное первенство | Обычно один видимый H1, описывающий тему, в main. Проверь logo/header, мобильную/desktop копию, hero + body RichText и скрытые дубли. Не оборачивай все карточки H1, не скрывай дополнительный H1 CSS ради теста. Несколько равнозначных заголовков разбери по смыслу и визуальному весу; исключение зафиксируй. Один H1 — политика проекта, не универсальное требование ранжирования Google. | G2, Y1 |
| S14 | Иерархия H2–H6 и дубли внутри страницы | Структура следует разделам, а не размеру шрифта; убери автоматическое повторение заголовка статьи в теле, бессмысленные одинаковые соседние секции, пустые headings. Повторяемые «Контакты»/названия секций на разных страницах не требуют искусственной уникализации. Для визуального размера используй CSS, а не произвольный уровень. | G1, G2, Y1 |

## D. Контент, навигация, ссылки, языки

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S15 | Страница отвечает реальному намерению | Оригинальные факты/услуги/товары, ясный первый экран и важный текст доступны без сценария согласия/логина, если страница публичная. Нет lorem ipsum, недостоверных обещаний, массового AI-спама, дорвеев/клоакинга/скрытых ключей. Проверяй владельца/автора/контакты и источники по типу контента; не придумывай E-E-A-T-сертификат. Изменения медицинского/юридического содержания требуют компетентного утверждения. | G1, G9, Y1 |
| S16 | Внутренние/внешние ссылки и breadcrumbs | Реальный `<a href>` на актуальный canonical, понятный anchor, нет битых ссылок/цепочек/JS-only обработчиков. Content Tree breadcrumbs и меню согласованы по назначению, не строятся из URL догадками. Paid links — sponsored, пользовательские — ugc при необходимости; не ставь nofollow на все внешние ссылки. Не покупай ссылки/не отправляй письма ради «оптимизации». | G8, G9, Y1 |
| S17 | Мультиязычность/региональность при наличии | Правильный lang и переведённый основной контент/метаданные, отдельные URL, абсолютные reciprocal hreflang, корректные коды и x-default при обосновании. Self-reference, все версии возвращают 200; canonical не схлопывает переводы в один язык. Нет принудительного IP/language redirect, скрывающего варианты от обхода. Реальный регион/NAP в Яндекс Бизнес/Google Business — только с правами и фактическим присутствием. | G6, Y1 |

## E. Head, social, изображения и разметка

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S18 | Meta/head санитария | Один источник title/description/canonical/robots/OG, charset/viewport без ошибок, нет случайного refresh и conflicting X-Robots. Не смешивай HTTP и HTML canonical с разными целями. `meta keywords` Google не использует; не делай его обязательной оптимизацией и не заполняй спамом. Защищённый head PCMS правится данными, не дублирующими theme-тегами. | G1, G2, G3 |
| S19 | Open Graph и X/Twitter cards | Тип по реальному контенту, title/description/url/site name/locale; og:url согласован с canonical. Для нужной карточки — управляемое доступное изображение, верные MIME/геометрия/alt, без защищённого/expiring URL. Core OG fallback: override → свой hero → опубликованный родитель Content Tree → site default. Нет картинки — не выдумывай asset и не делай всю страницу ошибкой индексации; согласуй реальную brand/social fallback. Смотри raw head и разрешённый preview, не обещай сброс чужого social cache. | O1, G10 |
| S20 | Картинки/иконка/видео | Информативный alt у смысловых img, пустой у декоративных; доступные src/srcset/sizes, размеры/aspect-ratio, оптимальный формат/сжатие. Значимые картинки видны роботу без click/scroll; hero/LCP не lazy, ниже сгиба можно lazy. Управляемые derivatives не выдумывай, проверь URL/MIME/404. Фавиконка через Site Identity, при наличии video — thumbnail/metadata/доступность и актуальные video guidelines. | G10, Y1 |
| S21 | Структурированные данные | Валидный JSON-LD, правильные типы по реальной странице и поддержке движка, стабильные @id/URL, согласованные Organization/WebSite/BreadcrumbList/Article и при наличии Product/Offer/LocalBusiness. Значения видны пользователю и истинны; нет конфликтующего raw JSON-LD из темы, фиктивного rating/цены/дат. Проверка Rich Results Test/Schema validator и Yandex validator по доступности. Синтаксическая валидность ≠ eligibility; поддержка FAQ/HowTo и иных rich features перепроверяется, не ставится на все страницы. | G11, Y1 |

## F. Рендеринг, мобильность, производительность

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S22 | Raw HTML и rendered DOM | Main content/links/head присутствуют в серверном HTML и совпадают с нормальным браузером. JS не удаляет canonical/robots/title и не создаёт конкурирующие теги. Ошибки JS/resources, hydration, blocked CSS/JS и cookie wall не скрывают целевое содержимое. Нет отдельной SEO-версии только для bot User-Agent. | G8, G12, Y1 |
| S23 | Мобильность/доступность | Одинаковый основной контент/метаданные/разметка на mobile, viewport/читабельность/отсутствие горизонтального overflow, рабочая клавиатура/фокус/ссылки/формы. Нет навязчивых interstitial и layout jumps. Не удаляй важную часть текста ради mobile score; изображения и touch targets проверяй на реальном viewport. | G13, Y1 |
| S24 | Core Web Vitals: полевая приёмка | Цели good: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 на 75-м перцентиле реальных визитов, отдельно mobile/desktop. При отсутствии CrUX/RUM — статус «полевые данные отсутствуют», а не выдуманный PASS. Не ставь персональный трекинг ради этих метрик; доступная агрегированная Search Console/CrUX информация и согласованный RUM имеют отдельные условия. | G14, G15 |
| S25 | Производительность: найденная причина и результат | Измерь репрезентативные шаблоны и тяжёлые исключения в фиксированных условиях; TTFB/cache/compression, critical CSS/fonts, размеры картинок, render-blocking JS, long tasks, third-party, preload только нужного, cache headers и immutable assets. Не включай unsafe-inline, публичный кэш private-данных и агрессивную компрессию без проверки совместимости. Сравни до/после; Lighthouse — диагностика лаборатории, не полевая гарантия и не цель ровно 100. | G14, G15, G10 |

## G. Поисковые сервисы и применимые расширения

| ID | Проверка и критерий | Исправление / отрицательная проверка | Основа |
|---|---|---|---|
| S26 | Владение, диагностика и переобход | С реальными предоставленными proof/доступом — GSC и Яндекс Вебмастер, нужный protocol/host/property. Проверь provider-side подтверждение, sitemap fetch, URL inspection/render, indexing/canonical и ошибки. Без доступа явно external pending; CMS 200 с proof не значит аккаунт подтвердил владение. Ни DNS, ни отправка третьим лицам без полномочий. | G1, Y1 |
| S27 | IndexNow и специальные indexing API | Только если доступно и нужно: действующий host/key, свежие changed/deleted canonical URL, bounded submission, provider response. IndexNow может помогать участвующим поисковикам, но не заменяет sitemap/обычный обход. Не используй Google Indexing API для обычных статей: его допустимые типы проверяются по текущей документации. Delivery ≠ indexing. | I1, G1 |
| S28 | Отраслевые/большие сайты при наличии | Магазин: реальные товары/варианты/availability/currency/shipping/returns и согласованный feed; local: реальный NAP/часы/адрес; news/video/image: профильные sitemap/метаданные по текущей поддержке; faceted/большой сайт: crawl budget/лог-анализ и ограничение ловушек. При отсутствии такого типа — обоснованный N/A. Не расширяй обычный корпоративный сайт фиктивными товарами и профилями. | G1, G7, G10, G11 |

## Условия завершения

Исправь все применимые контролируемые ошибки, отдельно обоснуй принятые trade-offs. Для каждого URL с ошибкой — результат повторной проверки либо точный блокер. Общие проверки шаблона покрывают все затронутые страницы; исключения проверяются отдельно. Не добавляй следящий сервис, юридический риск или поломку сайта ради балла SEO. В [отчёте](../assets/acceptance.md) не скрывай непроверенный остаток обхода и внешнюю приёмку.
